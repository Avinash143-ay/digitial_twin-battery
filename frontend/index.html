How To Use This Dashboard

Use this section as a quick manual for normal users. No terminal commands are required.

1) What is Quantization?

Meaning: Quantization uses a lighter math mode (INT8) instead of full precision (FP32).

Why: It can reduce memory and sometimes improve speed on certain hardware.

Trade-off: May be slightly less accurate, and on some systems it can be slower.

Recommended default: Keep FP32 unless your measurements show INT8 is better.

2) What is LoRA?

Meaning: LoRA is a lightweight way to adapt the model without retraining all weights.

Why: Faster updates on new battery data and smaller adapter files.

Merged: Best for deployment and inference.

Unmerged: Best when you want to continue adapter training.

3) Quick Start For New Users
  1. Go to Predict Mode or Compare Mode.
  2. Upload CSV input data (or generate constant current).
  3. Run prediction/evaluation and review charts.
  4. Use Performance Mode only if you need optimization settings.
4) How To Use Performance Mode
  1. Click Refresh to read current backend status.
  2. For Quantization: Enable INT8 Mode or Use FP32 Mode.
  3. For LoRA: Merge LoRA for deployment, Unmerge LoRA for adapter training.
  4. After switching, run one prediction to confirm behavior.
5) Recommended Defaults (Production)
  • Quantization: FP32 (unless benchmark proves INT8 is faster on target machine).
  • LoRA: Merged (for clean and efficient inference).
  • If training adapters again: switch LoRA to Unmerged temporarily.
